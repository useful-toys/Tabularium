- Decisão: cada decisão vigente tem um arquivo nomeado só pelo slug; quando muda, o arquivo é editado, a escolha anterior vai para alternativas descartadas e o histórico ganha uma entrada; a que deixa de valer é apagada, salvo se explica um item de fora de escopo
- Contexto: a pasta de decisões deve explicar o estado atual do produto, não virar um arquivo morto de escolhas superadas
- Alternativas descartadas
  - Decisões imutáveis com status substituída: a pasta cresce com o que não vale mais
  - Numeração sequencial no nome: com arquivos apagados, o número vira buraco e ID a manter
- Consequências
  - Ganha: tudo o que está na pasta vale
  - Aceita: decisões revogadas só no histórico do versionamento
